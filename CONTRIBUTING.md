# Contributing

## Documentation standard
Every technical page should answer:
1. What is this for?
2. What must be true first?
3. What action or command is required?
4. What result is expected?
5. How is success verified?
6. What commonly fails?
7. How can the user recover?
8. Which authoritative references support it?

## Safety
Destructive commands require an explicit warning and device verification. Never document a fixed disk path as universal.

## Source priority
1. ArchWiki / Arch Linux official documentation
2. Upstream project documentation
3. Hardware/vendor documentation
4. Reputable community documentation for edge cases

## Writing
Use concise technical English, define uncommon terms, explain placeholders, prefer testable commands, and keep troubleshooting close to the procedure.

## Validation
Review procedures against current upstream documentation and execute them in a disposable environment where practical.
